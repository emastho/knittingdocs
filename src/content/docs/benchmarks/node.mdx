This page summarizes Node.js benchmark runs for Knitting `0.1.24` on
`node 24.12.0 (arm64-darwin)`, recorded in March 2026.

## IPC (Node)
This benchmark measures round-trip communication between the main thread and
workers using different transports.
Knitting has the lowest overhead in this setup:

- `1` message: Knitting is about `5.2x` faster than worker `postMessage`, `12x` faster than WebSocket, and `29x` faster than HTTP.
- `25` messages: Knitting is about `3.5x` faster than worker `postMessage`.
- `50` messages: Knitting is about `3.3x` faster than worker `postMessage`.

## Knitting vs Worker (Node)
These charts compare the same payload types sent through Knitting and `worker_threads`.

### One message
With a single value per call, Knitting is faster in these measurements:

- For small primitives, Knitting is roughly `10-14x` faster than worker `postMessage`.
- Worker `postMessage` stays near `~10 µs/iter` even for tiny payloads.
- For larger payloads, Knitting still holds around a `4x` advantage (for example, big object: `4.15 µs` vs `15.74 µs`).

### 100 messages
At `100` messages per iteration:

- Primitive payloads are `~6-8x` faster with Knitting.
- Heavier payloads are about `~2.4-4.2x` faster.
- Batching improves throughput for both, but Knitting has lower overhead across the tested payload types.

## Call growth throughput (Node)
This benchmark increases payload size from `32 B` up to `1,048,576 B` (1 MiB) and reports
the time per batch with `batch=64`.

Using the `1048576 B` row (`avg`) from the `batch=64` run, one-way transfer throughput is:

- `string`: `46.54 ms/iter` -> `1.44 GB/s`
- `Uint8Array`: `8.95 ms/iter` -> `7.50 GB/s`

Interpretation:

- In this batch test, Node transfers `Uint8Array` payloads much faster than strings.
- For 1 MiB binary payloads, Node lands in the `~7.5 GB/s` range in this run.

## Efficiency under heavy tasks (Node)
<HeavyTaskPrimeTransferCaution />

This stress test computes prime numbers over a large range, then serializes and parses large JSON payloads:

```ts
const N = 10_000_000; // search range: [1..N]
const CHUNK_SIZE = 250_000;
```

Even under this heavier workload, parallel workers scale well:

- `main + 1 extra thread`: `~1.7x` faster than main only.
- `main + 2 extra threads`: `~2.3x` faster than main only.
- `main + 3 extra threads`: `~3.0x` faster than main only.
- `main + 4 extra threads`: `~3.5x` faster than main only.

## All types in Knitting
This benchmark covers primitives, structured values, collections, typed arrays,
errors, dates, symbols, and promise arguments. It also compares static and
dynamic payload allocation.
Results are reported for count `1` and count `100` to show both per-call latency and batched throughput.

Quick takeaways:

- At count `100`, primitive payloads are usually in the `~15-30 µs` range, while heavier structured/collection payloads can be `~120-300+ µs`.
- The static payload path is usually around `2x-4x` faster than dynamic allocator paths (for example: string `~3.4x`, JSON `~3.0x`, `Uint8Array` `~3.6x`, symbol `~4.1x` at count `100`).
