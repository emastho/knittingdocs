This page summarizes Deno benchmark runs for Knitting `0.1.24` on
`deno 2.6.6 (aarch64-apple-darwin)`, recorded in March 2026.

## IPC (Deno)
This benchmark measures round-trip communication between the main thread and
workers using different transports.
Knitting has the lowest overhead in this setup:

- `1` message: Knitting is about `3.7x` faster than worker `postMessage`, `4x` faster than WebSocket, and `10.5x` faster than HTTP.
- `25` messages: Knitting is about `12.2x` faster than worker `postMessage`.
- `50` messages: Knitting is about `12.5x` faster than worker `postMessage`.

## Knitting vs Worker (Deno)
These charts compare the same payload types sent through Knitting and Deno workers.

### One message
With a single value per call, Knitting is faster in these measurements:

- For small primitives, Knitting is roughly `25-30x` faster than workers.
- For string/array/object payloads, Knitting is usually around `4-6x` faster.
- For larger payloads, Knitting still holds a clear advantage (for example, big object: `6.37 µs` vs `27.45 µs`, about `4.3x` faster).

### 100 messages
At `100` messages per iteration:

- Primitive payloads are `18-35x` faster with Knitting.
- Heavier payloads are about `~7x` faster.
- Batching improves throughput for both, but Knitting has lower overhead across the tested payload types.

## Call growth throughput (Deno)
This benchmark increases payload size from `32 B` up to `1,048,576 B` (1 MiB) and reports
the time per batch with `batch=64`.

Using the `1048576 B` row (`avg`) from the `batch=64` run, one-way transfer throughput is:

- `string`: `19.89 ms/iter` -> `3.37 GB/s`
- `Uint8Array`: `11.61 ms/iter` -> `5.78 GB/s`

Interpretation:

- In this run, Deno transfers binary payloads faster than strings.
- For 1 MiB `Uint8Array`, throughput lands around `~5.8 GB/s`; string is closer to `~3.4 GB/s`.

## Efficiency under heavy tasks (Deno)
<HeavyTaskPrimeTransferCaution />

This stress test computes prime numbers over a large range, then serializes and parses large JSON payloads:

```ts
const N = 10_000_000; // search range: [1..N]
const CHUNK_SIZE = 250_000;
```

Even under this heavier workload, parallel workers scale well:

- `main + 1 extra thread`: `~1.8x` faster than main only.
- `main + 2 extra threads`: `~2.5x` faster than main only.
- `main + 3 extra threads`: `~3.2x` faster than main only.
- `main + 4 extra threads`: `~3.7x` faster than main only.

## All types in Knitting
This benchmark covers primitives, structured values, collections, typed arrays,
errors, dates, symbols, and promise arguments. It also compares static and
dynamic payload allocation.
Results are reported for count `1` and count `100` to show both per-call latency and batched throughput.

Quick takeaways:

- At count `100`, primitive payloads are usually in the `~20-50 µs` range, while heavier structured/collection payloads range from `~160 µs` to occasional outliers of several milliseconds.
- The static payload path is usually around `~1.8x-2.5x` faster than dynamic allocator paths (for example: string `~2.2x`, JSON `~2.5x`, `Uint8Array` `~1.8x`, symbol `~2.2x` at count `100`).
