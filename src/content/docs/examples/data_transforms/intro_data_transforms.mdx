These examples parse, validate, render, and compress data. They include the cost of
transferring inputs and results, so you can compare host and worker execution on
workloads similar to those in your application.

Start with the runnable example, then use its benchmark command to measure the
pattern on your machine. For a detailed performance discussion, see
[Hono server routes](/examples/data_transforms/rendering_output/hono_server).

## Which example should you start with?

**If you're validating incoming data** -- API payloads, form submissions, webhook bodies -- start with [Schema validation](/examples/data_transforms/validation/schema_validate). It demonstrates a basic validation pattern with Zod.

**If you're doing auth work** -- token verification, renewal, signature checking -- [JWT revalidation](/examples/data_transforms/validation/jwt_revalidation) shows how to offload HMAC crypto to workers using built-in Web Crypto (no external JWT library).

**If you're hashing passwords** -- [Salt hashing](/examples/data_transforms/validation/salt_hashing) is the heaviest per-call example. PBKDF2 is intentionally slow, so each call does substantial computation.

**If you're calling an LLM** -- [Prompt token budgeting](/examples/data_transforms/validation/prompt_token_budgeting) trims prompts to fit a token budget. The budgeting itself is model-agnostic.

**If you're rendering HTML** -- [React SSR](/examples/data_transforms/rendering_output/react_ssr) for basic server rendering, [React SSR compression](/examples/data_transforms/rendering_output/react_ssr_compress) to also test Brotli placement, or [Markdown to HTML](/examples/data_transforms/rendering_output/markdown_to_html) for a simpler pipeline without React.

**If you're generating documents** -- [PDF invoices](/examples/data_transforms/rendering_output/pdf_invoices) renders PDFs on workers, and shows how to return binary from a task without it silently arriving as a numeric-keyed object.

**If you're ingesting files** -- [LaTeX paper indexing](/examples/data_transforms/validation/latex_papers) parses real arXiv sources, and compares where to split a pipeline between the host and workers.

**If you want the full picture** -- [Hono server routes](/examples/data_transforms/rendering_output/hono_server) is a real HTTP server that combines SSR, JWT, and health checks. It's the closest to a production setup.

## What all these examples have in common

- Each includes a host-only baseline so performance comparisons are apples-to-apples.
- Worker tasks usually return compact results (counts, compressed buffers, status flags) rather than large raw payloads -- though [LaTeX paper indexing](/examples/data_transforms/validation/latex_papers) measures a case where returning 626 KB of text adds no measurable overhead because processing each item takes much longer.
- The same code runs in both host and worker mode, so you can compare behavior without changing logic.
